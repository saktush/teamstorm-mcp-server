# Plan: Sync TeamStorm MCP server to public API v1 (4.2x)

## Context

The repo pinned its API knowledge to an older `swagger.json` (untracked, now gone).
A fresh spec landed at `api-v1-4.2x.yaml` (OpenAPI 3.0.4, 104 paths / 170 operations /
190 schemas, 38 tags). A read-only probe established the baseline:

- 11 genuinely new endpoints, 0 removed, 0 operationId renames vs the old
  `openAPI-coverage-report.md` baseline (159 endpoints / 179 schemas).
- 76 of 78 client call sites in `src/client/teamstorm.ts` still resolve to a spec
  operation. The 2 that don't are the time-tracking pair, which call a non-public
  `/tasks/api/v1/...` base by design.
- The new spec carries real Russian `summary`/`description` text. The old one did not
  ("Has not description." everywhere) — `AGENTS.md` still records the old state.

The 11 new endpoints: `WorkitemTimeMetrics` (9), `WorkitemTimeMetricTemplates` (1),
`WorkCalendars` (1).

## Global Constraints

- **Spec file is the pinned source of truth**: `api-v1-4.2x.yaml` at repo root, committed.
- **No delete tools.** The project intentionally exposes no destructive MCP tools.
  Spec `DELETE` operations stay unimplemented and are marked as such.
- **Tool naming**: `teamstorm_<domain>_<action>`, enforced by
  `src/__tests__/tool-naming.test.ts`. New tools must satisfy it.
- **Every tool registers through its domain `index.ts`** and appears in
  `src/tools/toolsets.ts`. `src/__tests__/toolsets.test.ts` guards this.
- **Descriptions are Russian**, matching the existing tool corpus and the spec's own text.
- **Tests are nock-based** (`src/__tests__/integration/`). No live API calls in tests.
- **Verification gate**: `npm run typecheck && npm run lint && npm run test:run` must pass
  before any task is considered complete.
- **The time-tracking private base stays.** The public API has no POST for time entries
  and no per-workitem filter; the private `/tasks/api/v1` path is not removed.

## Task 1 — Drift audit (read-only, parallel fan-out)

Split all 76 matched call sites into 6 domain groups. For each client method, compare
against its spec operation: query parameters (name, required, type), request-body fields
(required/optional, types), and response schema shape vs the TypeScript type in
`src/client/types.ts`. Harvest each operation's `summary`/`description` for Task 4.

Groups: (1) workitems core, (2) attachments, (3) documents domain,
(4) folders + portfolios, (5) workspace reference data, (6) time tracking.

Output: one findings file per group under the plan workspace, each finding labelled
CONFIRMED (spec and code demonstrably disagree) or SUSPECTED (needs a live check).
No code changes in this task.

## Task 2 — Fix confirmed drift

Apply every CONFIRMED finding from Task 1 to `src/client/teamstorm.ts` and
`src/client/types.ts`, and to any tool that surfaces an affected field. TDD: each fix
gets a nock test asserting the corrected request or response handling first.

SUSPECTED findings are not fixed — they are recorded in the change report as
"needs live verification".

## Task 3 — Public time-tracking period tool

Add `teamstorm_time_entries_list_by_period` over
`GET /cwm/public/api/v1/workspaces/time-tracking-entries` (`GetTimeTrackingEntries`):
required `startDate`, optional `endDate`, `users`, `fromToken`, `maxItemsCount`.
Response is `TimeTrackingModelList` of `TimeTrackingEntryModel`
(`id`, `date`, `spentTime`, `description`, `createdAt`, `updatedAt`, `deletedAt`,
`deleteUserId`, `deleteUser`, `workitem`, `author`, `type`).

Leave `teamstorm_time_entries_list` and `teamstorm_time_entries_create` on the private
base untouched — the public API cannot serve either. New client method, new type, new
tool file, domain `index.ts` + `toolsets.ts` registration, nock test.

## Task 4 — Enrich tool descriptions from the spec

Backfill MCP tool and parameter descriptions from the spec's `summary`/`description`
text, for tools whose current description is thinner than the spec's. Mechanical,
wide diff across `src/tools/**`. Do not change tool names, parameter names, schemas,
or behavior — description strings only.

## Task 5 — Rewrite `openAPI-coverage-report.md`

Regenerate against 4.2x: every operation grouped by tag, implemented/not, mapped MCP
tool, fresh totals (170 operations, 190 schemas). The 11 new time-metrics /
work-calendar endpoints are marked **planned ("coming soon")**, not plain
NOT IMPLEMENTED. Preserve the existing report's per-endpoint annotations where the
endpoint is unchanged.

## Task 6 — API change report

New `docs/api-4.2x-change-report.md`: what 4.2x adds vs the old baseline, the full
drift table from Task 1 (CONFIRMED and SUSPECTED), what was changed in response, and
the unimplemented-surface inventory by tag with a note on what each would buy.

## Task 7 — Update `README.md` + `AGENTS.md`

Refresh tool counts, replace the "spec has no field descriptions" note in AGENTS.md's
Источники section (no longer true in 4.2x), point the spec source at the committed
`api-v1-4.2x.yaml`, and add the planned time-metrics tools to the roadmap.
